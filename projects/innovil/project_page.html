Innovil: A Souls-Like Boss Fight

Tags: unity, game-design, coding, blender, souls-like, github

Innovil is a recreation of a souls-like boss fight I have build completely fromm grounds up. It is the project I was the most passioned for at the time, trying to do all parts myself to build a satisfying fight. I have always been a great fan of the souls titles from Framsoftware. With that inspiration I developed an idea for a boss monster, even long before I started the development.

Click on this GitHub link to visit the github release page, where you can find the download to the game. Extract the folder, and execute the .exe file. The game is playable with an Xbox controller or when opened via Steam using the controller button mapping.

Planning the Project

Before I started with anything, I made a plan for each point in the process of developing this bossfight. Those include:

• define the idea and concept and mechanics
• code and implement the movement and camera behaviour
• character model + rigging + animations
• boss model + rigging + animations
• import the models and code the character abilities
• create stats and HUD
• code the boss behaviour
• implement a hit- and hurtbox system
• create assets for particles and environment
• add soundeffects
• build the environment and lighting

The Idea

I took the design of a mechanical beast I made in school, it was an great fit, also desiding the setting for me. For the player character I decided for him to be mechanical too, it would remove the part of weightpainting the body in blender, speeding up the process, same goes for the boss monster "Innovil".

3D Models, Rigging and Animations

Blender grows to ones hearth very fast, I was able to quickly model the player character and rig it easily. The Boss monster however had a unique body shape, but just after a few tutorials, I understood what to do and how to rig it best. The long arms are made of more than 20 pieces, so Inverse Kinematics were very necessary for the rig.

Each model has around 40 animations, which I made in blender. some animations are just as short as a stagger, some a whole attack combo. In the end I could finish both animation sets in a few weeks.

Movement and Features

I planned controls to be oriented on the Dark Souls franchise, a third person view on a character, able to walk 360°, but without jumping. The features were coded in C# as usual for Unity. The player can do the following actions:

• camera lock on and off
• running
• evading
• light attack combo (depending on previous input)
• heavy attack combo (depending on previous input)
• blocking with shield
• shoot projectile (6 slots)
• reload projectiles (3 per reload)
• slow or fast heal (depending on button hold duration)

Coding the character movement and moveset is the most enjoyable aspect in creating a game, at least for me. I would call this my first big project, while working on it I learned a lot what to do and what not. But there was also I deadline to hit, which means, I could not learn everything I wanted, and hat to cut corners. One of those corners I cutted was unfortunately the Animator of Unity. It was a mess, but a functionable one at least. I have learned for the future, that it is more organized, when handling the transitions via code, instead the animator transitions.

The Impact Shield Feature

When the player holds the shiled up, a bar appears going down until empty. this bar is the impact bar, it determines how well the player blocks an attack. The higher the bar is when the attack hits the shield, the more energy can be absorbed of the impact, adding up with the enery loss of the block itself. When blocking perfectly timed, the player gains the max amount of energy possible. When the bar is completely empty, no extra energy is gained. A blue flash appears instead of a red one, when the engery change is positive.

When the extra enery bar is completely filled through the impact absorbtion, the player is bale to reload the projectiles.
